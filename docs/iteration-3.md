# 第三轮：默认关闭与紧凑界面

## 行为约定

- 每个新 mpv 进程默认关闭 splay。仅保留鼠标入口和 Shift+s 入口，不连接、不显示状态、不接管 Enter。启用状态不写入连接历史。
- 启用和连接是两个动作。启用后可以配置或查看设置；只有用户连接时才建立网络会话。关闭会断开同步并清除当前会话聊天，不关闭媒体。
- 鼠标入口使用一个同步图标。能读取现有 uosc 控制条配置时，在当前进程的控制条中加入按钮，保留其他按钮及设置；不写入用户配置文件。没有可用布局时使用独立小图标。
- 图标展开短菜单，第一项始终是启用/关闭。连接设置、成员、聊天记录和房间管理进入独立页面，避免把所有字段和成员铺在首页。
- 仅在启用、连接成功、服务器支持聊天且已加载媒体时接管 Enter；打开聊天后由 mpv 输入框处理 Enter 发送与 Esc 取消。其他菜单或输入框打开时让出 Enter，关闭 splay 后恢复原有键位。
- 首次房间为空。连接或创建房间前必须填写或明确选择房间，不能静默加入 Default。旧版自动恢复的 Default 占位值不再自动填入，历史中的该值仍可手动选择。
- 未填写房间时也可保存服务器、昵称等草稿；完整连接组合必须包含房间。保留现有去重、多进程合并及错误时保护原文件的约束。

## 实现分工

`splay.lua` 管理启用状态、表单、分级菜单与聊天输入。`splay_overlay.lua` 只负责图标、弹出菜单和状态呈现，不直接处理协议。原生历史模块允许空房间草稿，完整连接组合的校验仍然严格。

UI 转发的状态含 `enabled`，原生协议状态无需增加 UI 开关。小菜单模型由主 UI 产生，覆盖层发送动作名回主 UI，避免两处各自维护功能逻辑。

## 验收重点

- 默认关闭、启用但未连接、连接中、已连接、关闭后的显示和键位均正确。
- 普通 Enter 原有动作可恢复；聊天二次 Enter 发送、Esc 取消，不拦截其他菜单。
- 首次连接要求房间；修改其他字段后重启仍恢复草稿；旧历史和完整组合继续可用。
- 原生 mpv、uosc 以及用户所用 uosc 配置的隔离副本均检查布局；点击范围不覆盖进度条。
- 原生历史改动通过专项测试，并使用真实播放器及未修改的官方服务器检查端到端路径。
