# 第二轮：连接记忆、状态显示与聊天

> 本文保留第二轮实现时的范围。后续维护者已授权公开发布；当前许可和下载入口见 [README](../README.md)。

用户于 2026-10-14 要求实现本轮功能。主 Agent 负责方案、整合和验收；三个互不重叠的实现任务均明确指定 GPT-6.1 Sol、high 推理强度。此文记录范围和接口，实际测试结果另记。

## 用户可见行为

- 默认入口改为 `Shift+s`，服务器 `syncplay.pl:8999`，昵称 `splayuser`。用户已有 `input.conf` 绑定仍优先。
- 记住手动填写的服务器、端口、昵称、房间和 TLS 策略，重启播放器可恢复；保留多组完整连接组合以及字段历史，支持选择和手动输入。
- 历史仅保存非密码字段。切换连接组合不复用上一组密码；选择历史只填表，连接仍需手动操作。
- 左上角显示当前房间的准备情况、操作者暂停/恢复/跳转信息和短期聊天消息。颜色区分准备、播放事件和聊天，显示可关闭。
- 增加房间聊天输入及本连接当前房间聊天记录，切房/断开后清空，不将聊天写入历史文件。遵守服务器是否启用聊天及字符长度能力。
- 鼠标移近底部时显示同步面板、准备和聊天按钮，放在进度条上方；隐藏时不拦截鼠标。无 uosc 也能操作。

## 关键边界

历史使用当前 mpv 配置目录中的 `splay-history.json`，通过跨进程锁、读取最新内容后合并、同目录临时文件及原子替换写入。损坏文件或写入失败必须显示错误并保留旧数据。仅保存白名单字段，不写媒体 URL、密码或聊天。

连接字段优先级为：内建默认值 → `splay.conf` 首次默认值 → 已记忆的上次填写值。界面外观等其他选项继续由 `splay.conf` 控制。新播放器实例不会自动联网；已连接的实例换视频继续保留自身连接，未连接的实例也不会因为换视频而自动连接。

核心发布 `splay-event`：`schema:1`，`type:chat|playback`，递增 `id`、`username`，以及 `text` 或 `paused/position/seek`。心跳不反复产生播放提示；切房和重连重置事件基线。聊天实际通过官方 `Chat` 消息传输，渲染层始终按文本转义，不能将消息解释成 ASS 标签或 mpv 命令。

UI 继续接收 `splay-state`，新增 `chat_supported` 和 `chat_max_length`；将状态和事件转发给独立显示脚本。显示脚本提供 `overlay-toggle-status`、`overlay-toggle-buttons`，通过 splay 的原有命令入口操作核心。

## 验收范围

- 保留此前播放、跳转、权限、重连、TLS 和隐私测试。
- 官方客户端与插件双向聊天、中文/表情/特殊字符、长度限制、禁用聊天、跨房隔离。
- 历史跨进程恢复、多组合、去重、并发保存合并、错误文件保留、密码和媒体字段不落盘。
- 原生/uosc 的历史选择及聊天输入，状态截图、按钮实际点击、隐藏与区域外点击不被抢占。
- 已知标准宿主及用户提供的 mpv 二进制/uosc 5.12，在隔离配置中验证；不能把此测试称作整个整合包和浏览器调用链均已认证。
- 最终安装包包含三份运行文件，不修改用户其他配置；仓库继续私有。
