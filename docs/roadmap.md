# 开发路线与验收条件

所有功能阶段均未开始。仓库建立和文档整理不代表首版完成。

## 阶段 0：项目建立

- 明确 Windows 优先、独立可选插件优先、后续集成播放器的方向。
- 初始化 Git，整理架构、上游参考和首版验收要求。
- 创建 GitHub 私有仓库并验证本地与远端提交一致。
- 记录后续技术验证项，不提前声称兼容所有整合包。

## 阶段 1：宿主与界面验证

- 选择一个明确版本的 Windows x64 mpv，验证原生插件加载和退出清理。
- 验证 DLL 与 Lua 双向消息、属性观察和窗口内输入。
- 无 uosc 时可打开面板；有 uosc 时可使用自有菜单。
- 记录实际配置目录、禁用脚本和独立配置参数的影响。
- 验证不会覆盖既有配置或干扰整合包已有快捷键。

验收：从命令行及一个实际浏览器调用链启动 mpv，均可打开插件入口；未连接时正常播放，不访问同步服务器。

## 阶段 2：连接与房间

- TCP 连接、协议握手、服务器密码、能力协商和心跳。
- 验证 STARTTLS/证书处理及明确的失败、降级行为。
- 加入和切换房间、成员列表、准备状态。
- 受控房间创建或加入、操作员认证、权限提示。
- 清晰区分密码错误、服务器不可达和正常断开。

验收：连接未修改的官方 Syncplay 服务端，和官方客户端互相可见，房间与准备状态一致，普通成员无法越过受控房间权限。

## 阶段 3：播放同步

- 双向播放、暂停、跳转，以及后加入房间的位置对齐。
- 延迟估计、纠偏与本地/远端操作的反馈抑制。
- 区分用户暂停、缓冲、媒体加载和远端应用状态。
- 断线提示、重连后的状态确认、退出后的独立播放。
- 当前媒体不重新加载，原有请求参数和字幕继续有效。

验收：至少两个真实播放器实例，其中一个是官方 Syncplay 客户端。覆盖本地文件和可跳转网络点播，测试快进/暂停交错、延迟、重连、多窗口和退出清理。记录测量环境及同步误差，性能阈值在原型实测后制定，不提前声称毫秒级同步。

## 阶段 4：可用首版与公开准备

- 提供只包含自有插件文件的 Windows x64 安装包及卸载说明。
- 验证原生 mpv、uosc、至少一个整合包和一个浏览器调用场景。
- 写明最低版本、测试过的版本、未覆盖的启动方式与已知问题。
- 确定项目许可证；若使用第三方代码或组件，保留所需声明。
- 检查发布内容不含本机配置、凭据和私有媒体信息。
- 在首版达到可用标准后，按用户的公开发布安排处理仓库可见性和版本发布。

## 后续方向

根据使用反馈评估聊天、共享播放列表、可信媒体地址共享、其他系统，以及固定版本 mpv 的集成发行包。首版不承担平台资源解析、视频转发或同步服务器管理面板。

## 尚待验证的选择

- 实际使用的 mpv 整合包、架构和版本。
- 原生代码语言、网络/TLS 依赖及 Windows 构建方式。
- 原生界面所需的最低 mpv API；console 被关闭时如何提示或回退。
- 断线后继续独立播放还是暂停等待的默认行为。
- 凭据保存方式、连接收藏和多实例行为的细节。

这些选择应由原型和实际使用场景推动，不阻碍先建立私有项目。
